# @deepseek-ai/dsh-client-ui-collaboration

[English](README.md) | 中文

天然多智能体协作的 TeamRun 控制台。每个任务均从 Lead 与 1 至 8 名专家开始，界面展示任务发起、组队阶段、Task Profile、Team Charter、协作拓扑、团队名单、经过白名单处理的能力元数据、权威任务账本、Lead 控制台、Team Blackboard、运行时协作协议与公开协作时间线

根组件通过注入的 `useCollaboration` selector Hook 读取权威快照，并通过 `createRun`、`retryFormation` 和 `terminate` 执行命令。权威数据源位于 UI 包之外，协作 store 仅持久化导航、筛选、选中 id 与任务草稿，不保存 TeamRun、任务画像、团队章程、专家绑定、任务、资产、裁决、质量门、控制器状态、失败记录或结果

`team_formation_failed` 会以任务未开始的明确审计终态展示，界面不会把 Lead 单智能体执行呈现为团队成功。重试会创建并选中新 TeamRun，原失败 TeamRun 保留为不可变审计记录

现有的会话级智能体右侧面板仍保留，用于旧协作会话的有界子会话工作摘要与关键对话展示，不暴露推理块或执行流水

任务板从运行时投影展示依赖就绪状态、负责人、进度、资源范围与冲突。公开时间线展示观点、质疑、回应、评审、裁决、资产与 Lead 最终交付等类型化协作记录，并明确排除模型私有思考。只有权威 `final_delivery` 事件存在时，界面才会突出展示最终交付

Lead 控制台将自动检测的健康信号与 Lead 已写入账本的动作明确分开，展示健康度、最后进展、停滞任务、重复工作、质量失败、推荐恢复动作、已完成干预，以及由权威任务、资产、决策与质量门计数聚合的 Task / Progress Ledger

Team Blackboard 展示权威 `artifacts`、`decisions` 与 `qualityGates` 账本。资产行只展示类别、评审状态、actor、关联任务、媒体类型和更新时间等版本化元数据，不嵌入正文，也不伪装已具备正文读取能力。决策与质量记录保留版本、actor 身份、关联关系、摘要与结果，界面绝不从时间线文本推断这些业务记录

已完成 TeamRun 会展示由已完成任务、已采纳资产版本、质量门评审人、已通过门禁和已采纳 Lead 裁决组成的交付来源链。失败门禁和返工状态保持明确呈现，不会被折叠成普通执行活动

P6 协作协议视图仅读取权威 `run.protocol` 投影。强制模式任务会展示由拓扑生成的运行时规则、质疑轮次和每专家消息上限、总使用量、每个席位的质疑、评审与求助权限、允许目标、剩余预算，以及带消息追踪 id 的质疑线程状态。接近耗尽、已耗尽、轮次封顶和计数异常都会明确呈现，界面提示与运行时强制策略也保持视觉分离

Legacy 或 P6 之前的快照使用受控空状态，界面不会从时间线文本或 Team Charter 重建协议策略

## 模型体验

### 协作控制台

#### 模型看到的内容

没有来自此 UI 包的内容。它不添加协调提示词、系统提示词段落、工具 schema 或隐藏模型指令，团队规划与协作编排归属于注入 `CollaborationPort` 背后的协作运行时

#### Token 影响

界面控制台不产生 Token 影响，Token 仅由权威协作运行时及其会话消耗

#### KV Cache 影响

界面控制台不产生 KV Cache 影响

## 已知限制与延后工作

- 确定性测试 fixture 覆盖 1 名专家组队中、8 名专家执行中、强制与 legacy 协议、正常、接近耗尽与已耗尽的专家预算、待回应与已回应质疑线程、停滞与返工控制状态、任务依赖、权威资产与决策账本、失败与通过质量门、已完成交付来源链、类型化公开讨论、组队失败、重试生成新 TeamRun、取消与刷新恢复展示
- P5 与 P6 视图只读展示权威投影，协议准入、任务修改、协作消息、控制器干预、裁决准入、资产正文读取、质量门执行与最终交付准入仍由协作运行时负责
- 旧右侧面板仍通过协作标题前缀识别早期主协调会话
