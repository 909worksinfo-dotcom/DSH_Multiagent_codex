# Coze PRD 交付检查表

## A. 目标与范围

- [ ] 标题能说明具体业务能力或用户体验。
- [ ] 背景明确用户、场景、问题和当前影响。
- [ ] 本期目标可观察、可验收，不是抽象口号。
- [ ] 本期做、本期不做和后续计划边界清晰。
- [ ] 原型能力没有被误写成生产能力。

## B. 功能闭环

- [ ] 每个核心功能都有入口、用户动作、系统响应和验收点。
- [ ] UI 文案、展示位置和触发条件明确。
- [ ] 覆盖空态、加载、成功、取消/忽略、失败和过期/失效等适用状态。
- [ ] 说明失败或取消后数据是否改变。
- [ ] 重试、重复提交、刷新恢复或幂等要求按需说明。
- [ ] 外部依赖、前置条件和降级方式明确。

## C. 角色、权限与端

- [ ] 角色权限使用矩阵表达。
- [ ] 关键写操作说明谁能发起、谁能确认、谁被拦截。
- [ ] 权限校验不只依赖前端展示，必要时写明服务端校验。
- [ ] 权限在流程中变化时有处理规则。
- [ ] 各端状态为 `resolved`、`follow_up`、`out_of_scope` 或 `pending`，并说明原因。
- [ ] 跨端共享语义一致，端独有交互另行说明。

## D. 数据与度量

- [ ] 核心指标有指标名、计算口径和目标值或待定。
- [ ] 比率指标写清分子、分母、统计范围和时间窗口。
- [ ] 埋点事件有触发时机、维度、端和验收方法。
- [ ] 成功、失败、权限拦截等关键漏斗可被观测。
- [ ] 修改记录、审计或历史范围有清晰口径。

## E. 安全、隐私与风控

- [ ] 明确是否涉及用户输入、AI 生成内容、个人信息或历史记录。
- [ ] 涉及时写出审核、权限、留存、分享或用途变化的评估要求。
- [ ] 覆盖越权、误写、刷写、频控、冲突和失败不覆盖等风险。
- [ ] 未完成的安全或法务结论标为待确认，不擅自下结论。

## F. 排版与语言

- [ ] 标题层级不超过四级，同级标题语法一致。
- [ ] 复杂比较使用标准表格，顺序流程使用有序列表。
- [ ] 一段一个结论，避免连续长墙文本。
- [ ] 状态、事件、文件、命令和环境变量使用行内代码。
- [ ] UI 文案使用中文引号。
- [ ] 没有“优化体验”“相关处理”“友好提示”等不可验收措辞。
- [ ] 没有复制参考文档的项目专属链接、分支、人员或结论。
- [ ] 未知内容统一写 `待定`，没有编造信息。

## G. 最终交付

- [ ] 读者能在一分钟内理解问题、方案和范围。
- [ ] 产品、设计、研发、测试、数据和合规能找到各自信息。
- [ ] 待确认事项集中列出，并优先标明阻断项。
- [ ] 文档包含可直接执行的下一步，而不是只描述愿景。
