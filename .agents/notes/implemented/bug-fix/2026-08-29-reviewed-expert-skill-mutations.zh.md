# Agent Note: 审阅阶段专家技能变更

Status: implemented

[English](2026-08-29-reviewed-expert-skill-mutations.md) | 中文

## Problem

自由文本协作修改此前只会强制每位专家的技能数量下限。指定某位专家并替换、增加或移除具体技能的要求只会保留在提示文本中，确认页投影和真正创建的子专家仍使用不可变蓝图默认技能

## Decision

Task Profile 现在会保留有顺序的指定专家本地技能变更。规划会在精确选中的 roster 中解析每个目标，确定性地执行替换、增加或移除，并把最终本地技能集合保存到对应计划席位

界面展示的本地技能 id 与内置中英文别名都可使用。变更后的每个技能集合都会在发布可审阅方案前通过选中预置解析。专家目标不存在、技能不可用、目标有歧义、技能集合为空或违反产品最小技能数时，系统会封闭失败，不再生成未变化的确认页

ExpertCatalog 接受仅对本次调用生效的技能集合，不修改已配置蓝图。ExpertRuntime 会绑定该审阅集合，把技能内容摘要持久化到专家描述符，将技能列入专家初始提示，并在恢复与漂移校验时重新解析同一组持久技能名称

## Verification

回归测试覆盖指定专家替换、有顺序的增加与移除、自然语言别名、不可用技能不生成计划事件、传递到真实组队创建、调用级目录解析，以及运行时提示和描述符

正式 Web 组合测试使用生产预置，把技术分析专家的技能替换为三项可用能力，并在确认前验证精确持久计划

## Alternatives considered

**重写部署蓝图** 不予采用，因为单个任务的修改不应改变后续任务或部署所有的目录

**只展示请求技能而不绑定** 不予采用，因为确认页是执行合同

**接受任意名称并把失败延迟到组队阶段** 不予采用，因为用户必须在确认前看到有效且可执行的团队

## Consequences

审阅阶段技能修改现在会同时改变可见专家配置和真正子专家绑定。已有任务和不可变历史计划保持不变，新生成方案会把每位专家的精确技能集合贯穿确认、组队、恢复和公开投影
