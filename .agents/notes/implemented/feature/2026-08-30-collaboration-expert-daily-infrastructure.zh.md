# Agent Note: 多智能体专家的日常任务基建

Status: implemented

[English](2026-08-30-collaboration-expert-daily-infrastructure.md) | 中文

## Problem

协作专家虽然是真实且可续接的 Agent 会话，但角色蓝图会把标准预置缩减为少量工具白名单，通用委派会把审批固定为 `never`，组队还会复制主协调智能体创建时的模型路由而不是用户当前选择的模型。因此，专家名单可能显示已挂载，但专家实际上并不具备日常会话已有的 Agent 基建

## Decision

所有随产品交付的协作专家蓝图都使用 `standard` 预置和空拒绝列表。角色、人格约束、技能、任务分配、协作协议、任务预算和质量门禁继续限定专家行为，但不再从专家作用域移除标准日常工具

组队时先读取主协调智能体的实时模型选择，再应用专家蓝图的显式覆盖。不可变专家绑定会记录实际生效的 Provider、模型、可选推理强度、Token 上限、完整或受限工具状态、沙箱模式和审批策略。新建与恢复的专家作用域都会安装日常会话模型 API 使用的同一个模型选择引用，因此后续查询或切换模型会修改真实请求路由，而不是只修改界面副本

专家在发布前会写入精确的委派沙箱和审批覆盖。专家会继承组队时主协调智能体的实际权限状态，需要审批的专家工具调用会进入既有主机审批链路。非协作场景的通用子智能体继续保留原有的 `never` 失败关闭默认值

任务方案确认页和专家团队页只展示安全基建元数据，包括模型继承或选定路由、完整或受限工具集以及权限策略，不会暴露密钥、文件路径、提示词、人格文本或绑定摘要

该功能发布前创建的绑定继续保持不可变。缺少基建字段的旧绑定仍可读取，并显示为旧任务未记录，而不会被追溯升级或错误描述

## Verification

运行时测试覆盖主协调智能体实时模型继承、专家模型选择的真实安装、通用委派之后恢复为实际 `ask` 审批、随产品交付蓝图的完整工具访问、冷启动安全投影、客户端深拷贝、模型 API 共用引用，以及方案确认页和专家团队页展示

协作、子智能体、审批、主机、客户端运行时和 UI 回归测试继续保护专家恢复、角色约束、市场技能挂载、任务执行和现有日常会话

## Alternatives considered

**继续使用角色工具白名单。** 评审专家看到的工具更少，但这不符合每名专家都具备同等日常基建的要求，而且新增标准工具时所有专家蓝图都需要同步修改，否则会被静默遗漏

**只把主协调智能体模型复制一次到子智能体参数。** 这种方式保留原来的创建逻辑，但会遗漏界面里用户当前选择的模型，也不能让专家接入日常会话的模型 API

**把所有子智能体的默认审批策略都改成 `ask`。** 这会扩大协作功能之外的行为范围，削弱通用委派现有的失败关闭契约，因此权限升级只作用于不可变 ExpertRuntime 绑定

**读取时重写旧绑定。** 这会让旧任务看起来已经升级，却无法证明其当时的真实运行方式，也会破坏任务快照不可变约束

## Consequences

协作专家现在与日常 Agent 共用标准工具、模型选择、沙箱和审批底座，同时保留任务专属角色与有界协作规则。绑定 Schema 和安全浏览器契约新增一个可选基建记录，专家启动时多安装一个作用域模型选择器，而随产品交付的专家只会在任务确有需要时使用其可见的完整工具集
