# Agent Note：分阶段团队执行计划

状态：已实现

[English](2026-08-29-staged-team-execution-plan.md) | 中文

## 背景

自动组队此前会提交 roster 与任务 DAG，但自动推断的任务清单可能过于粗略，计划没有为每个步骤持久指定执行者，主协作界面也只展示扁平清单，因此难以验证执行是否完整遵循计划

## 决策

自动推断的调研分析、产品方案或软件开发请求现在会展开为有界的领域专属执行 DAG，调用方显式提供的 workstream 保持不变。planner 会把依赖层分组为不可变的串行或并行阶段，并把每个 workstream 分配给一个 roster slot

组队流程会先完成全员 provisioning，再通过仅 Lead 可用的 `assign` 迁移把每个 pending 任务绑定给计划中的 active 专家，同时不会启动仍被阻塞的任务。路由 `task` 消息必须引用已就绪任务并发送给该任务的确切 owner。既有单消息协作接力保持不变，因此并行阶段表示任务依赖相互独立，而不是模型回合同时运行

主协作会话会从权威运行时 DAG 推导阶段，在阶段和单个任务上分别展示串行或并行标记，并为每个步骤显示本地化执行 Agent 名称。任务清单描述会规范空白并限制为最多 60 个 Unicode 字符，权威描述保持不变。已完成步骤继续使用删除线并降低视觉权重

## 验证边界

该契约由 profiler/planner、持久 fold、任务板、orchestration、模型路由、Host 组合与客户端渲染多层测试覆盖。缺少新增可选计划字段的历史 orchestration payload 仍可解析并保持不可变
