# Agent Note: 协作身份配色与结构化路由消息

Status: implemented

[English](2026-08-28-collaboration-identity-colors-and-structured-routes.md) | 中文

## Problem

公开协作时间线把发送者身份与消息类别混在一起，同一 Agent 会因任务、资产、评审和移交记录而改变颜色，粗重的左侧竖线也会与正文竞争视觉注意力。路由消息以带展示性串行移交前缀的扁平文本保存，读者需要从同一段无层次文本中辨认上下文、下一步、接收者选择和实际消息。如果只从新消息删除前缀，不可变历史事件仍会在界面中保持不一致，恢复逻辑也会继续依赖展示文案

## Decision

协作界面根据参与者身份生成一种确定配色。Lead 使用稳定的中性色，已编组专家使用稳定的团队顺序，未知参与者使用确定性哈希兜底。头像、作者强调色和消息表面在所有消息类型中共享该身份色。消息类型继续用文字标签表达。头像、消息色面和消息分类标签均不使用边框或轮廓阴影，相邻消息行依靠留白而不是分隔线组织

公开内容投影器会清理中英文旧串行移交标记，并把路由文本解析为正文、上下文摘要、下一步、接收者选择和消息等语义区块。每个区块拥有独立标签和字体层次，普通非路由消息仍使用单一正文区块。清理只发生在展示层，不修改持久化历史

新的串行路由直接包含结构化公开字段，不再写入仅供展示的前缀。路由器会在当前发送者空闲后推进，重新读取权威上下文，规划一个下一步动作，并只选择一名符合条件的接收者。恢复逻辑识别结构化字段前缀，同时兼容旧存储格式，因此界面文案不再是主要恢复键

## Verification

投影测试固定旧版和当前内容的标记清理与区块提取。组件测试固定同一参与者跨消息类型配色一致、不同参与者配色不同、结构化区块正确渲染以及旧标记不出现。工具适配器测试固定持久化路由和后续路由均不包含标记。类型检查、聚焦 lint、生产构建和完整 GUI 测试覆盖包集成。本地浏览器对持久协作任务的检查确认旧标记显示数量为零，头像、消息色面和消息分类标签的边框数量为零，路由消息已结构化，并且 Lead 与三名专家拥有稳定且不同的配色

## Alternatives considered

**按事件类型为消息着色** 被拒绝，因为同一 Agent 会在任务、资产、质疑和评审事件中改变颜色，削弱快速识别发送者的能力，并让颜色同时承载两种含义

**只修改 CSS** 被拒绝，因为字体无法可靠拆分仍处于同一文本节点中的字段，新生成内容也会继续暴露展示标记

**重写历史事件** 被拒绝，因为 TeamRun 事件是不可变审计记录。展示时兼容处理可以移除过时文案，同时不修改持久证据

**继续把标记作为恢复判据** 被拒绝，因为展示文案不是持久协议。结构化字段识别负责当前恢复，旧格式识别保证历史任务仍可继续

## Consequences

读者可以通过颜色持续追踪同一 Agent，并按语义快速浏览路由内容，不会再把发送者身份和消息类型混淆。无边框处理减少视觉噪声，改由色面、字体层级和留白表达结构。新记录不再暴露实现导向的移交标签，旧记录无需迁移即可一致展示。界面和路由器需要保留一小段旧内容兼容解析，团队顺序也会成为专家确定性配色的一部分
